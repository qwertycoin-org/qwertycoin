# Core v2.0.4 canary (historical)

This candidate combines display-only EPoSE endpoint telemetry with the completed
epoch-31 mainnet checkpoint at height 23039. The Core product version is 2.0.4;
the compatibility version is 2.0.4.0. Nix packages derive their candidate version
from the same source declaration. This document records the pre-release canary.

Core [v2.0.4](https://github.com/qwertycoin-org/qwertycoin/releases/tag/v2.0.4)
was subsequently published from immutable source
`1e479cc9feda48e07dd07ba6abcb89ca3934b5e2`. The official CLI archives and Docker
image contain the daemon and both wallet programs at `2.0.4-release`; the
daemon-only canary layer below is not the published release payload. The stable
client channel retains the disclosed public-test EPoSE audit-readiness boundary.

The checkpoint is append-only: hash
`cb30509efe6dbe1641578dd6a8f28944272f7281228ce4fcf00f7b6c38b78345`,
cumulative difficulty `0x2923e77ff2e`. Seed-00, Seed-01, and the public Explorer
were checked independently on 2026-10-16. Alternative branches crossing a reached
checkpoint are rejected by the existing checkpoint rules. No hardfork,
emission, reward, genesis, or EPoSE qualification parameter changes are included.

The telemetry response remains an unsigned informational self-report, outside
the signed endpoint descriptor and all consensus decisions. Cached descriptors
for other service nodes must not expose the responding daemon's telemetry.
Old nodes remain compatible and do not report a version through this extension.

Required CI builds the exact PR head and retains checksum-bound copies of the
tested daemon and focused test binaries. These short-lived artifacts are not
public release assets and do not publish Docker tags. An authorized single-node
canary may layer only that daemon over the immutable existing runtime, with
explicit source/binary provenance and a distinct canary image channel. Other
executables in that runtime retain their prior version.

Before accepting the canary, verify the binary checksum and reported 2.0.4
version, preserved genesis and prior canonical tip, independent seed agreement,
unchanged service identity and volumes, RPC restrictions, dependent Explorer
health, zero unexpected restarts, and a retained automatic rollback path.
Explorer version visibility depends on its next successful endpoint poll; the
telemetry must not be interpreted as proof of EPoSE upgrade compliance.
